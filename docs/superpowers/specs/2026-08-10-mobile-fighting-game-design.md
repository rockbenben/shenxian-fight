## 一句话

轻量爽快向的手机横屏 1v1 格斗游戏：东方神话角色、CD 技能 + 一键大招、绚丽演出，纯前端离线可玩。

## 定位与取舍

- **爽快向，非硬核**：无搓招、无取消系统、无目押。技能走 CD + 气槽，一键释放。深度让位于「上手 5 秒、一指爽」。
- **单机打 AI**：街机模式 4 关，零后端。联机（WebRTC）明确排除在 v1 外。
- **手机为主**：横屏锁定，竖屏显示「请横屏」提示层。桌面键盘（WASD + JKUI…）作为免费副产品保留，用于调试。
- **PWA**：沿用 015 的 vite-plugin-pwa，离线可玩。

## 技术栈

- Vite + React 19 + TypeScript + Canvas 2D（沿用 015 thousand-lives 技术栈）
- **零新增运行时依赖**。不用 PixiJS/Phaser：格斗爽感 90% 来自演出编排（顿帧/震屏/慢镜/白闪/残影/粒子），Canvas 2D + `globalCompositeOperation='lighter'` 足够。若特效撞到天花板，渲染层已隔离，可换 Pixi 而不动战斗逻辑。
- 测试：vitest。音效：zzfx 风格 Web Audio 合成，零音频文件。

## 架构

```
React（UI 壳）          标题 / 选人 / 街机流程 / 结算 / 设置 / HUD / 触控层
      ↕ 只在场景切换时通信，战斗中零 React 重渲染
Canvas（战斗内核）      固定步长 60Hz 逻辑 + 按刷新率插值渲染
      ↕
数据层（纯 JSON/TS）    角色表 · 招式表 · 骨骼关键帧 · 特效编排 · AI 权重
```

三条硬边界：

1. **战斗内核不 import React**。`Battle` 类：`tick(p1Input, p2Input)` 推进一逻辑帧，
   状态就挂在实例上（`p1`/`p2`/`winner`/`events`…）。可脱离 UI 运行与测试——
   **这一条落地了**，`src/engine/` 至今不 import React。
   （当初这里写的是「输出 `BattleState`」，那个类型从未存在过；实际做法是「实例即状态」。）
2. **逻辑与渲染分离**：逻辑固定 1/60s 步长（accumulator 模式），渲染插值。掉帧不改变判定；60Hz/120Hz 手机行为一致。
3. **招式是数据不是代码**：一招 = 一份 JSON（判定帧窗、伤害、硬直、位移、骨骼关键帧、特效编排）。加招不动引擎。

逻辑分辨率固定 960×540，等比缩放 + DPR 适配，所有坐标数学在虚拟空间进行。

## 操作

- 左手：虚拟摇杆（移动 / 上跳 / 下蹲）
- 右手 6 键（拇指扇区）：普攻 · 技能×3 · 大招 · 防御
- 触控层输出抽象 `InputFrame`（方向 + 按键位图），内核只认 `InputFrame` → 键盘映射免费。

## 战斗系统

**状态机**：`idle / walk / jump / attack / hitstun / block / down / super`。攻击分 `startup → active → recovery`，仅 active 帧有判定。被击进入 hitstun，硬直中不可操作。

**判定**：全 AABB 矩形。招式定义 hitbox，角色常驻 hurtbox，相交即命中，一招对同一目标仅判一次。

**防御与破防**：按住防御，正面减伤 80% + 微硬直；近身普攻自动变投技，投技破防。

**普攻连段**：3 段，按一下自动接下一段，每段命中才接。

**气槽**：打人/被打积气，上限 100。

**招式数据结构**：

```ts
type Move = {
  id: string;           // "nezha_super"
  damage: number;
  startup: number;      // 前摇帧
  active: number;       // 判定帧
  recovery: number;     // 后摇帧
  hitstun: number;      // 对方硬直帧
  knockback: { x: number; y: number };
  cooldown: number;     // 技能 CD（普攻为 0）
  meterCost?: number;   // 大招耗气（50 / 100）
  motion: Keyframe[];   // 骨骼关键帧
  fx: FxEvent[];        // 特效编排
};
```

**每角色 8 招**：

- 3 段普攻连段
- 3 个必杀技（CD 技能，各带特效）
- 2 档大招，共用一个大招键，一键自动放当前最高档：
  - **奥义**（气 ≥50，按钮亮银）：中型演出——暗场 + 特效爆发，无时停
  - **超必杀**（气 =100，按钮亮金）：全套演出——时停 → 镜头急推 → 暗场高亮 → 放招 → 慢镜命中 → 恢复，附 1 秒无敌

招式总量 4×8=32，带演出的「绚丽招」20 个（12 必杀 + 8 大招）。

**AI**：状态机 + 权重随机，不做行为树。每 10 帧决策一次，按距离段（远/中/近）从可用招式按权重抽取。权重表即难度：第 1 关反应慢爱空挥，第 4 关会防御、抓后摇。每关一份权重 JSON，共用同一 AI 函数。

## 演出系统

**8 种粒子基元**（引擎提供，招式 JSON 按帧编排触发）：
`burst`（爆发）· `trail`（拖尾/残影）· `beam`（光柱）· `ring`（冲击环）· `spark`（火花）· `flash`（全屏闪）· `glyph`（法阵/符文，Canvas 几何绘制）· `shockwave`（多层同心环近似径向扭曲）

```ts
{ frame: 8, type: 'beam', color: '#ff6a00', width: 120, angle: 0 }   // 三昧真火
{ frame: 8, type: 'ring',  color: '#ffd700', radius: [0, 300] }      // 金色冲击环
```

绚丽 = 基元多层叠加 + `lighter` 混合发光。全角色复用同一套基元，加新招特效 = 拼 JSON。

**打击感四件套**（全局系统，命中自动触发，强度按 damage 分级）：

1. 顿帧 hitstop：命中双方冻结 3-8 帧，大招 12 帧
2. 震屏：随伤害分级，衰减曲线
3. 受击白闪：2 帧
4. 音效：zzfx 合成（打击/挥空/防御/破防）

**镜头**：虚拟相机跟随两人中点，按间距缩放。超必杀走专属演出流程（全角色共用流程，仅招式本体不同）。

**背景**：每关一张 AI 生成场景图（天宫/火焰山/东海/幽冥），2-3 层视差滚动。

## 美术管线

- **AI 立绘 + 代码骨骼动画**：每角色一张 AI 立绘，切成 ~10 个透明部件（头/躯干/大臂×2/小臂×2/大腿×2/小腿×2/武器），所有动作用关键帧插值驱动。加角色 = 一张图 + 一份 JSON。
- **画风约束**：扁平/卡通/描边风（切件骨骼不适合写实风，关节旋转会露馅）。
- **降级路径**：若切件质量不过关 → 剪影 + 描边风格（部件为色块，切割零成本）。

## 测试策略

vitest，只测战斗内核（可脱离 UI 运行）：

1. 判定帧窗口正确性（startup 帧不命中、active 帧命中、recovery 帧不命中）
2. 连段/硬直状态转移
3. 两个 AI 互打 1000 帧不崩溃、不死锁

渲染与手感不写自动化测试，靠训练木桩真机调。

## 实施顺序

1. **色块阶段**：矩形色块人 + 完整战斗内核 + 打击感四件套，先把「一拳爆爽」调对（美术零依赖）
2. **管线验证**：哪吒一个角色跑通「AI 生图 → 切件 → 骨骼动画」全流程，确认不露馅（本步失败走降级路径）
3. **批量生产**：其余 3 角色 + 大招演出 + 街机流程 + 4 张背景
4. **收尾**：PWA、结算画面、平衡性调整、README

## 风险登记

| 风险 | 对策 |
| ---- | ---- |
| 切件质量翻车（最大风险） | 实施顺序 2 单角色先行验证；降级路径为剪影风 |
